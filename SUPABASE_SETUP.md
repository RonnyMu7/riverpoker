# RIVER — подключение Supabase

Этот репозиторий — статический сайт. Публичный ключ Supabase можно использовать в браузере только вместе с корректными RLS-политиками; секретный `service_role` ключ нельзя помещать в HTML или GitHub.

## 1. Создать таблицы и политики

1. Откройте проект Supabase `vpeomywcwjijxdkhgqnn`.
2. Перейдите в **SQL Editor → New query**.
3. Скопируйте содержимое файла `supabase-schema.sql`, выполните запрос.
4. В **Table Editor** проверьте, что созданы `river_events`, `river_players`, `river_requests`, `river_settings` и `river_site_content`.

Политики специально не дают посетителям читать заявки с телефонами/Telegram или менять настройки сайта. Публичная форма может только добавлять заявку. Админские операции ещё не подключены: для них нужен проверяемый серверный/Edge Function слой или отдельная роль с ограниченными политиками.

## 2. Важно перед публикацией

- Не добавляйте `service_role` ключ в `index.html`, JavaScript или публичный репозиторий.
- Публичный ключ не является секретом, но безопасность обеспечивается RLS.
- В этой версии форма в `index.html` всё ещё сохраняет заявки локально в браузере. Создание таблиц само по себе не подключает сайт к базе.
- После настройки нужно подключить отправку формы к Supabase и протестировать: новая заявка создаётся, а анонимный посетитель не может прочитать таблицу заявок.
